# 项目长期记忆：协作方式与成本复盘

记录日期：2026-10-17。由用户明确要求写入项目，作为后续协作依据。执行规则见 [AGENTS.md](../AGENTS.md)。

## 为什么这次迭代成本偏高

用户在试玩后发现问题属于正常的产品探索。成本上升主要来自工作组织与执行方式：

1. 设计探索与开发发布混在一起。核心的“领任务—询问人物—听线索—找到目标”尚未稳定，就持续扩展辅助功能，带来返工。
2. 人物应有的对话理解与实际关键词规则存在差距，技术边界说明太晚。不断补规则只能改善已知情形，不能等同于通用语义理解。
3. 每条反馈都立即实现、截图、测试、同步源码和发布，放大了工具调用、上下文和等待成本。
4. 音色兼容和源码托管连接故障多次重复排查。应先定位根因，再决定重试。

复盘不包含实际账单统计，不能据此声称具体费用或节省比例。

## 后续默认流程

### 讨论和收集

先理解问题，将相关反馈合并成一轮。只在缺失信息会改变实现或体验时提问，不把每条意见立即变成代码任务。

每轮使用简短清单：

- 要解决的问题和期望行为。
- 本轮范围与暂不做的部分。
- 实现方式、能力限制。
- 两三个可操作的验收场景。
- 当前阶段：待讨论、待实施、本地待验收或待发布。

### 明确实施后，统一本地修改

用户明确要求实施后，集中完成该轮改动与必要检查，不重复请求细碎授权，不顺带增加辅助功能。后续反馈先归并到当前范围，扩展方向记录为下一轮讨论。

以最小完整体验验证价值，优先验证高风险依赖。本项目先验证语音识别、音色与语速、任务相关提问，以及领任务到完成的一条完整路径。

### 验收与发布分别进行

默认交付本地预览与验收结果。用户明确要求发布后才进行远端源码同步、打包和上线；不要把方案认可、功能修改授权或上一轮发布授权自动当成本轮上线授权。

发布失败应保留成果、报告阻塞。只有部署工具确认成功才称为“已上线”。不未经请求创建自动重试或监控任务。

## 保留的产品与技术背景

- 面向青少年，以英语听说为核心；学生主动行动，教练像军师，指导而不代做。
- 已确认的核心玩法见 [学生主导，教练陪玩](core-gameplay.md)：AI 教练与真人教练遵循相同权限边界，可同行或语音陪伴，只协助理解和分析，不参与任务的实际完成。任务由学生亲自推进。
- 游戏中优先听、重听、慢速重听和开口交流；英文、中文与文字输入作为按需辅助。语言背包保留学习文字。
- 人物线索需要任务相关提问，不能随便说一句就授予。允许多种可理解表达，不强制背固定句子。
- 当前对话为预设内容和规则判断，浏览器提供语音能力，本地 Silero VAD 控制三秒静音结束；未接入开放式 AI 对话，不评估发音或完整语义。
- 真人教练联机属于产品设想，当前未实现。
- 不同网址和浏览器的本地存储不共享，测试环境不能直接代表线上用户的音色或进度。

## 下一轮仍需讨论，尚未授权实施

- 决定人物继续采用有限规则，还是接入 AI 语义理解。先比较体验、维护成本、运行成本和最小验证方式。
- 非任务问题如何自然回应，例如 “Do you see a boy?” 应接住“男孩”的话题并澄清，且不授予 Pip 线索。目前仍是通用澄清回复；之前举出的自然回答只是设计建议。
