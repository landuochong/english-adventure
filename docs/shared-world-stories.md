# 统一世界与多地图故事设计

2026-11-12，现行方向；本地实现继续位于 feature/future-campus-2026-11-12。

## 世界组织

校园是主地图，科学中心、庭院、咖啡馆、商店、图书馆等属于校园内的区域。人物有稳定身份和世界坐标，故事引用人物，不为每篇故事复制一个独立页面或重建人物系统。学生自由行走，AI/真人教练只陪伴、分析与提供建议，不执行学生的任务。

当教学情境不适合校园（如户外、森林探险），使用独立地图。不同地图共用人物交谈、语音输入、线索判断、背包、任务进度和完成反馈；每张地图单独定义边界、地形、碰撞、人物位置和出生点。不得把森林等未实现地图作为可玩入口。

## 故事接入约定

故事入口配置 world、region、giver、people、目标位置与交付位置、物品呈现类型、学习词汇、asrScene、完成对白。地图注册在 campus-world.js；故事注册和运行接口在 campus-missions.js。当前运行接口为 config、state、marker、hint、act；场景层只读取状态并提交学生动作。

- 每次只推进一个当前故事，人物每次处理一个当前任务。阶段完成后问号变为文本标记，下一次需要该人物时再变问号。
- 学生先听场景语言背包，再到人物身边领任务；点击发布者直接听委托，询问对象需要学生开口。
- 多轮对话可累积信息、允许不同顺序和纠错；教练、重听和装饰物不会授予任务进度。
- 目标物需满足线索条件并实际走近才发现，领取和交付为学生主动动作。
- 切换故事前结束录音和播报，不把上一故事的线索、携带物或对白用于下一故事。
- 新故事必须配置识别主题与核心词汇。识别提示不是答案硬替换；原始识别结果保留。
- 新地图实现自己的场景构建器并复用上述任务接口；未来跨地图切换要管理资源释放和出生位置，不能只更换地图名称。

六个日常故事由 campus-daily-missions.js 适配原 scene-engine.js / scene-conversation.js。3D 距离与视线通过后，适配层才转换到旧引擎内部坐标调用；不是让远处人物自动完成对话。保留原有关键词规则、纠错和多轮信息累积。物品任务在最后汇报前增加真实发现和领取，最后必须手动交付；非物品任务不创建无关道具，最后显示“确认汇报”。

所有故事配置识别场景与语言背包，识别测试覆盖八个注册故事的场景提示，仍使用 Whisper small 与 3 秒静音。场景提示不做答案替换。

## 验证

- 六个日常故事均有统一地图适配层完整任务测试：远程/隔墙不推进、教练不改状态、多轮交流、领取前不能跳至汇报、最后手动确认/交付。
- 使用浏览器实际生成的小地图碰撞矩形重建行走范围，检查 17 位人物和 5 个物品任务领取点从出生点均可到达附近。
- 浏览器通过文字辅助完整走通购物故事：问价、选帽、走近发现、领取、带回、汇报、交付、三星结果；完成后继续下一故事会更换语言背包与识别场景。实际走过庭院→商店→图书馆。浏览器无错误。
- 真人麦克风口音准确率尚未逐个故事复测；测试通过不代表所有口音都能识别正确。

## 当前边界

- 八个内置故事已接入同一校园。购物是游戏内预设情节，不接入支付；问路是获取出行信息，不模拟乘车或博物馆参观。天气任务是策划公园活动，不代表已制作独立森林地图。
- 森林/户外独立地图、跨地图资源切换仍待实现；不提供假入口。
- 课程自动生成故事仍用原试玩入口，尚未自动投放 3D 世界；后续需区域/人物绑定编辑与通路校验。
- 当前对话为规则和预设对白，非开放式 AI。真人教练联机尚未实现。
- 状态为当前会话内状态，刷新重新开始。未发布，本轮未自动提交。
