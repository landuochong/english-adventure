# 从一课生成听说故事：模板设计 v0.1

日期：2026-10-22。本文保留初始设计；当前已实现本地提取、故事生成、编辑检查与配置加载试玩，实际范围和验收见 [设计记录 0.27](design.md) 与 [使用指南](user-guide.md)。未实现的扩展仍以本文为规划。

## 目标与第一版范围

学完一课后，作者提供课内材料，确认词汇、短语与语法，再补充实际想练习的情境，生成可编辑的互动故事。复用地图、人物交谈、语音、教练和任务引擎，不为每课重新写一套应用。

第一版只跑通一课、一个故事、3～5 个情节的完整流程。提供一个已有地图布局；每个情节必须有新信息、问题、选择或行动，不能把一段独白拆成几句冒充多个情节。批量生产、新地图生成、开放式 AI 人物、真人联机、账号和发音评分不在本轮范围。

教学材料尚未提供。[示例](story-template-example.md)是根据现有点餐场景编写的演示材料，不是真实教材提取结果，也不是已经能运行的新关卡。

## 作者流程

| 步骤 | 作者看到与可以编辑的内容 | 进入下一步的条件 |
|---|---|---|
| 1. 提供课程 | 第一版先粘贴课文、词表及语法说明；填写年龄、水平、时长和需求场景 | 材料可读；图片/PDF 提取另行设计，不能假装已支持 |
| 2. 确认学习重点 | 词汇、短语、语法、对应原文依据；可增删、修改，追加英语表达 | 作者确认；无依据的推断标为“待确认” |
| 3. 生成故事草稿 | 人物动机、情节顺序、信息差、关键交互及完成条件 | 覆盖学习目标，并通过结构检查 |
| 4. 编辑与试玩 | 可改台词、难度、允许表达、追问；从开头或指定步骤试演 | 修改关键目标或条件后重新检查关联步骤 |
| 5. 保存关卡版本 | 保存课程重点与故事配置，保留版本关联 | 人工验收完成；保存不等于发布上线 |

生成阶段拟使用 AI，但服务商、运行位置、费用与调用方式尚未选定。运行阶段第一版建议继续用受约束的任务引擎；生成 AI 不得直接产生可执行 JavaScript 或任意正则并在客户端执行。

## 课程重点与学习目标

每个学习条目有稳定 ID、类型（词汇/短语/语法）、英语内容、中文含义、课内来源、练习方式和关联步骤。来源分为：课内明确出现、用户补充、AI 建议补充；不把补充词冒充课内重点。

数量由课程和学生水平决定，初始建议每故事选择 6～10 个核心词、3～5 个常用短语、1～2 个语法目标；超出时提示作者拆成多个故事，而不是全部硬塞。准备页教表达，不展示任务的具体答案或目标位置。

目标区分“听懂后行动”和“主动表达”。语法要有交际用途，例如 would like 用于表达需求，过去时用于汇报已发生的事情。作者给出可接受的多种表达及典型反例。信息说清但目标句型尚未练到时，人物可自然追问，回顾提示补练；默认不因没有逐字套用标准句扣住任务。规则未覆盖的合理表达应澄清，不判断学生发音差。

## 模板数据结构（设计约定）

填写版见 [story-template.md](story-template.md)。未来配置可用 JSON 存储，以下是内容职责，不是当前加载接口。

| 字段组 | 必需内容 |
|---|---|
| metadata | 模板版本、故事 ID/版本、课程 ID/版本、标题、年龄/难度、目标时长、草稿/已验证状态 |
| learning | 学习目标列表、来源依据、课内/补充标记、听力/口语练习方式、步骤映射 |
| world | 地图模板、人物 ID/位置/职责、学生与教练起点 |
| story | 背景、人物需求、学生任务、开场引导、3～5 个情节 |
| steps | 步骤 ID、前置条件、交谈人物、触发方式、人物掌握的信息、预设回应、输入要求、完成后效果 |
| dialogue | 待收集的信息项、允许值、别名表达、确认状态、缺项追问、歧义确认、修改与否定策略 |
| coach | 分级提示、词义解释、基于已获得信息的分析；不拥有完成任务的权限 |
| speech | 英语音色/语速策略、识别场景词汇；与任务正确答案分开存储 |
| completion | 必须完成的行动、最终汇报、庆祝回应及学习回顾 |
| acceptance | 正常路径、乱序表达、纠正、识别错误、无关输入、重复操作和重置用例 |

关键步骤使用有限类型：听取委托、询问信息、收集多项需求、确认选择、交付/汇报。前置条件仅用引擎定义的条件（例如“某步已完成”“已获得某条线索”），效果仅允许引擎定义的状态变化。表达匹配不把关键词出现当成无条件成功：要处理否定、矛盾和当前交谈对象。

## 运行时交互契约

- 学生控制移动、询问、选择和交付。教练可以同行、解释、出主意；AI 或真人教练都不能替学生领取、填写信息项、获取线索或提交完成。
- 开场说明环境及下一步；点击任务发布者的问号先听任务。其他人物待回应时保持问号；独立喇叭用于重听，阶段结束后人物标记可变为喇叭。
- 人物每轮从整句话提取当前步骤相关信息，顺序不限，允许一轮多项、跨轮积累，只追问缺项。例如先说饮料，再说食物，也能完成。
- 信息项状态：未提供、待确认、已确认。识别歧义只进入待确认，不授予进度。Yes/No 只作用于明确的当前问题。
- 明确更正替换对应信息，其他已确认信息保留；不确定是更换还是追加时先问。完成状态改变后旧确认不可跨步骤继续生效。
- 获得任务前、未走近、人物错误、无关话语、重听、教练提示、取消录音都不授予线索。后续动作仍需遵守合理前置关系，步骤内自由顺序不代表可跳过剧情。
- 世界状态与语言理解分开：卖完的商品不能交付；人物不能知道尚未发生的事。分支必须能重新汇合或明确结束，不产生死路。
- 游戏以听说为主，转写/中文按需展开。可重听、慢放、问教练和重听学生原声；文字输入为替代方式。
- 主动返回主页重置当前冒险，保留音色/语速；场景内导航保留进度。编辑后保存新版本，不能把旧进度套入结构不同的新版本。

## 识别上下文与答案隔离

识别提示只使用场景主题、公共词汇、当前已公开的问题及已确认对话。禁止传入隐藏位置、正确线路数字、任务约束的正确组合或预期完整回答。原始识别结果保留；“候选解释”不能伪装成原始转写。

当前 Whisper 后端使用固定场景白名单。模板引入新词汇时，需要新增经过检查的上下文配置读取流程，不能声称任意生成故事已经自动获得识别提示支持。

同一录音对比无提示/场景提示，必须包含非标准答案、其他数字和无关话题，防止提示把错误答案强行修正为正确答案。模型识别出可接受句子也不能直接改变任务状态，仍由任务引擎检查。

## 生成与检查流程

生成输入为已确认学习重点、作者需求、固定模板规范和引擎支持的能力。课程内容仅作材料，不作为执行指令。输出为故事配置草稿和目标覆盖表，必须标明新增表达。局部重生成优先只改所选情节，保留作者修改；影响前后依赖时给出关联改动供复核。

生成后先做结构与可达性检查：ID 唯一、人物存在、前置依赖无循环、每个信息项有可听来源或合理自主选择、所有分支可收尾、关键目标有练习位置。再人工检查英语、逻辑、难度和是否提前泄露答案。不能仅因结构合法就称为教学质量合格。

未通过检查的故事保持草稿，不进入学生关卡列表。AI 服务不可用时允许手工填写模板，不生成虚假的成功结果。

## 现有代码复用与后续开发顺序

| 现有部分 | 后续处理 |
|---|---|
| scene-engine.js 的任务、人物和词汇 | 拆分固定引擎与故事配置，保留旧场景兼容路径 |
| scene-conversation.js 的信息项和多轮澄清 | 抽成有限交互类型；用配置声明槽位与追问，不动态执行生成代码 |
| app.js 的地图、教练、问号、回放 | 复用组件；新增作者入口和配置加载边界，不复制一套游戏 |
| whisper_asr.py 的场景提示 | 经检查的公共词汇配置，不读取任务答案字段 |

建议开发顺序：先手工填写一个模板并用加载器跑通，再接课程重点编辑，最后接 AI 提取/生成。这样能先确认“生成什么才可运行”，避免先生成大量无法承载的剧情。

## 第一版验收

1. 作者能从一课确认核心词、短语、语法，添加自定义表达；每项来源可追溯。
2. 故事有 3～5 个有因果联系的情节，至少一次信息变化、一次多轮交流和最终汇报。
3. 正常完成；乱序补全；单项纠正不丢其他信息；歧义不确认不推进；替代方案可完成。
4. 随便说话、提前汇报、重复重听、找教练代答均不能完成；没有因分支或重复点击卡死。
5. 关卡默认听说优先，语言背包不提前出现任务答案，回顾不伪造发音或掌握度评分。

## 下一步所需材料

需要一课的真实课文或词表、主要语法，以及学习者大致水平。年龄、时长和补充场景可以先用建议值，由作者在学习重点页确认。正式生成服务的选择与费用在进入代码实施前确认。本轮交付仅包含设计和填写示例，未开发、未发布、未提交 Git。
